# Paladin — сценарий показа

Длительность: ~15 минут. Всё работает локально: Docker (Neo4j, PostgreSQL, SIFT-песочница) и Ollama с `qwen3.5:9b`.

Логин в дашборд: **admin**, пароль — `DASHBOARD_ADMIN_PASSWORD` в `.env` (его же печатает `start_demo.ps1`).

---

## Вечером накануне (10 минут)

1. Запустить Docker Desktop и Ollama.
2. `.\start_demo.ps1` — все 7 шагов должны быть `OK`.
3. Открыть https://localhost:8888 → **Advanced → Proceed to localhost** (сертификат самоподписанный; браузер запомнит исключение).
4. Войти, пройти **Акт 1** целиком один раз — это и есть репетиция.
5. `.\stop_demo.ps1`.

## За 15 минут до показа

1. Docker Desktop и Ollama запущены (иконки в трее).
2. Ноутбук **на зарядке**, режим питания «Максимальная производительность» — LLM на батарее заметно медленнее.
3. `.\start_demo.ps1` — чистый старт, пустой дашборд.
4. В браузере: войти, убедиться, что выбран режим **Human-in-Loop**, закрыть лишние вкладки, масштаб 110–125% для проектора.
5. Во втором окне терминала заранее набрать (не запускать):
   `.venv\Scripts\python -m pytest tests\test_attack_shadow_paladin.py -s -q`

## Ход показа

### Вступление (1 мин) — что такое Paladin

> Локальная автономная система безопасности: логи, почта, чаты и звонки → граф Neo4j → корреляция → локальная LLM предлагает реакцию → программный верификатор решает, можно ли её выполнить. Ничего не уходит в облако.

Показать дашборд: живой фоновый трафик идёт, инцидентов нет.

### Акт 1. Инсайдер выкачивает данные (5 мин) — главный акт

Вкладка **Scenarios** → `Data Exfiltration` → сотрудник `Alexei Petrov` → **Execute Scenario**. Вернуться на вкладку инцидентов.

| Что происходит | Когда | Что сказать |
|---|---|---|
| Два инцидента (HIGH и CRITICAL) на экране | ~4 с | Корреляция: доступ к файлам выше допуска + массовое скачивание |
| Сводка LLM, предложено `ISOLATE` | ~6 с | Модель предлагает, но не решает |
| Плашка **APPROVAL REQUIRED: ISOLATE** | через 45 с | Таймаут оператора истёк, но изоляцию система сама не выполняет — только по решению человека |
| Кнопка **Forensics** — план и находки | ~1 мин у первого инцидента, ~2 мин у второго (расследования идут по очереди) | Расследование в изолированной Docker-песочнице: без сети, улики только для чтения. Нашли C2-адрес, хеш дроппера, DNS-запрос в pcap. Каждая находка сверяется с выводом инструмента — зелёная метка **Verified** |

Пока идёт расследование (~1 мин), заполнить паузу рассказом про граф (вкладка **Graph**, ID инцидента) или про политику реагирования.

Затем нажать **Approve** → «Confirmed exfiltration» → сотрудник изолирован.

Ключевая фраза: *«LLM — советник. Решения о блокировке людей принимает либо человек, либо жёсткие правила, которые модель обойти не может».*

### Акт 2. Атака на самого Paladin: «заблокируй CEO» (3 мин)

**Scenarios** → `External Exfiltration` → сотрудник `Igor Smirnov — CEO` → Execute.

Через ~4 с: инцидент CRITICAL, LLM предлагает `ISOLATE`, но плашка — **APPROVAL REQUIRED**, в конце сводки: *Cannot apply ISOLATE to protected entities — operator decision required*.

> Злоумышленник может попытаться использовать систему защиты как оружие — заставить её заблокировать руководство. Аккаунты из списка защищённых система не тронет никогда, даже в автономном режиме и даже после ошибочного одобрения.

### Акт 3. Автономный режим (2 мин)

Переключатель вверху → **Autonomous**. **Scenarios** → `Brute Force Attack` → `Pavel Novikov` → Execute.

Через ~15 с — красная плашка **AUTO-EXECUTED**: аккаунт изолирован без участия человека.

**Сразу вернуть режим Human-in-Loop.**

### Бонус, если есть время (1 мин). Пароль в корпоративном чате

**Scenarios** → `Credential Sharing` → любой сотрудник → Execute. Коллега пишет ему в личку `admin / Pr0d_DB_2025!` — NLP-анализатор распознаёт пароль в открытом виде, инцидент заводится на обоих участников переписки.

### Финал. Доказательство устойчивости (2 мин)

Во втором терминале запустить заготовленную команду. Через ~10 с — отчёт **OPERATION SHADOW PALADIN — DEFENSE REPORT**: 8 стадий атаки на саму систему (инъекции в LLM, захват дашборда, выход из песочницы, подделка доказательств), все **REPELLED**.

> Модель в этом тесте специально «взломана» — она выполняет любые инструкции злоумышленника. Система всё равно держится, потому что защищают её программные барьеры, а не добросовестность модели.

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `start_demo.ps1`: Docker FAIL | Запустить Docker Desktop, дождаться *Engine running*, повторить |
| `start_demo.ps1`: Ollama FAIL | Запустить Ollama из меню «Пуск», повторить |
| Браузер: «Подключение не защищено» | Advanced → Proceed to localhost |
| После сценария нет инцидента 10+ с | Проверить, что выбран сотрудник; посмотреть `logs\paladin.log` |
| Сводка LLM долго «Forensic analysis in progress…» | Модель занята расследованием предыдущего инцидента — подождать ~30 с, продолжать рассказ |
| Forensics: «No forensic plan» | Расследование ещё в очереди (по одному за раз) — открыть через минуту |
| `start_demo.ps1`: «already running» | Уже запущено — просто открыть https://localhost:8888, или `.\stop_demo.ps1` и запустить заново |
| Всё сломалось | `.\stop_demo.ps1`, затем `.\start_demo.ps1` — ~1,5 минуты |

## После показа

`.\stop_demo.ps1` — остановить (данные сохраняются), `.\stop_demo.ps1 -Purge` — удалить демо-базы.
